## 2. Logic Chain

1. **CPU Limit (Error 1102) Mitigation**:
   - Heavy AST-heavy libraries (`exceljs`, `jspdf`, `html2canvas`) previously inflated the SSR/RSC worker chunk, triggering the 10ms–50ms CPU timeout on Cloudflare edge isolates.
   - Deferring them behind `next/dynamic({ ssr: false })` and runtime `await import()` completely isolates the server-side RSC payload, dropping CPU execution time to <5ms during SSR.
   - Adding `limit(300)` and 10-item client-side pagination (`paginatedTransactions = filtered.slice(start, start + itemsPerPage)`) prevents DOM node explosion and hydration lag.

2. **Tenant Isolation Verification**:
   - Because `where('clinic_id', '==', cData.id)` is applied at the Firestore query level alongside `phoneVariants`, Firestore returns only records belonging to the authenticated clinic.
   - Phone variants are generated by `getPhoneSearchVariants(phone).slice(0, 10)`, supporting local (`010...`), international (`+20...`), and raw digit formats while adhering to Firestore's `in` filter limit.

3. **Routing Stability**:
   - When requests arrive on custom subdomains (e.g. `zizo.yalla-clinic.com/admin/accounts`), Next.js middleware rewrites the route while `pathname` seen by client-side hooks remains `/admin/accounts`.
   - Checking both prefix styles (`/clinic/${slug}/admin` and `/admin`) prevents false-positive redirects to the landing page or infinite auth checks.

## 3. Caveats & Adversarial Findings

### Finding 1 [Minor]: Firestore Composite Index for Large Historical Data
- **Location**: `src/app/clinic/[slug]/admin/accounts/page.tsx:87-91`
- **Issue**: The query uses `where('clinic_id', '==', cData.id), limit(300)` without `orderBy('createdAt', 'desc')` to avoid crashing on undeployed Firestore composite indexes.
- **Risk / Blast Radius**: In a high-volume clinic with >300 total appointments, Firestore returns the first 300 documents in default document-ID order rather than the latest 300 appointments.
- **Recommendation**: In Milestone 3 (Database & Security Rules hardening), deploy the composite index `appointments: clinic_id ASC, createdAt DESC` and re-introduce `orderBy('createdAt', 'desc')` to guarantee the most recent 300 transactions are fetched.

### Finding 2 [Minor]: Missing try/catch in `handleExportExcel`
- **Location**: `src/app/clinic/[slug]/admin/accounts/page.tsx:305-331`
- **Issue**: `handleExportExcel` lacks a `try/catch` wrapper around `await import('@/lib/excelExport')` and `exportComprehensiveFinancialReportExcel(...)`.
- **Risk**: If the client is offline when clicking export, the dynamic import rejection will not be caught with a user-facing toast.
- **Recommendation**: Wrap in `try { ... } catch { toast.error(...) }`.

### Finding 3 [Informational]: Next.js 16 Proxy Convention Warning
- **Location**: Build logs
- **Notice**: Next.js 16 emits `⚠ The "middleware" file convention is deprecated. Please use "proxy" instead.`
- **Assessment**: Non-breaking for M1; can be addressed in upcoming maintenance or code cleanup tasks.
